## Findings and follow-up

1. **Intermittent sign-in module load / retry failure.** At approximately 17:49 Budapest time, LoginPage-AasR5NkA.js failed to load. The in-page Retry did not recover and exposed the router error page. Direct HTTP inspection returned 200 and a full reload recovered. Cause is unconfirmed: do not label this a missing deployed file without further evidence. Reproduce with browser Network logging and consider improving lazy-route recovery. Evidence: login-load-failure.jpg, login-retry-failure.jpg, console-errors.json.
2. **Reserved-stock presentation inconsistency.** Cukkini is labelled available in catalog and details, while details prevent purchase because stock is reserved. Ordering protection works, but the mixed messaging deserves review. Reservation state can change during testing, so this is an observation rather than a proven stock defect.
3. **Cart disappearance is inconclusive.** The cart was empty on a later return after successful persistence and checkout tests. No order was placed and no successful manual remove action occurred. Re-test this flow with timestamps and network capture before attributing it to expiry or a defect.
4. **Legal copy is visibly provisional.** Suitable to track as an existing UAT launch dependency; no legal correctness assessment was performed.
5. **Persistent Data Protection directory remains an operational follow-up.** User reported login working after enabling the application-pool user profile. This report does not independently confirm authenticated login, configured key path, or persistence after pool recycle.
